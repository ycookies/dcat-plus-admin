# 当前角色切换

默认情况下，历史版本的多角色用户会合并所有角色的权限。启用当前角色模式后，一个后台会话只使用一个角色的菜单和权限；用户可在导航栏中无须重新登录地切换已分配角色。

## 启用

先执行迁移：

```bash
php artisan migrate
```

迁移会向管理员表增加可为空的 `default_role_id` 字段。该字段不使用数据库外键，以兼容自定义角色模型和多数据库连接。

然后在 `config/admin.php` 配置：

```php
'permission' => [
    'active_role' => [
        // 启用单当前角色授权；false 时保持历史多角色权限并集。
        'enable' => true,

        // 管理员表中保存默认角色 ID 的字段名。
        'default_column' => 'default_role_id',
    ],
],
```

扩展包默认关闭该功能以保持升级兼容；新项目可直接启用。

## 默认角色

在“系统管理 - 管理员”的编辑页：

1. 先勾选用户拥有的角色。
2. 从“默认角色”选择其中一个角色。
3. 用户下次登录时将以该角色进入后台。

默认角色必须属于该用户。若角色被移除、默认角色为空或数据已失效，框架会回退到该用户可用角色中的第一个，并更新 `default_role_id`。

## 导航栏切换

当用户有多个角色时，导航栏显示当前角色和下拉列表。切换会请求：

```text
POST /admin/dcat-sys/roles/switch
```

接口仅允许切换当前用户已绑定的角色，并受登录态与 CSRF 保护。切换成功后会刷新顶层页面，使菜单、Iframe Tabs 页面和 Grid/Show 操作按钮全部按新角色重新渲染。

## 授权规则

开启后，下列 API 仅依据当前角色：

- `allPermissions()`
- `can()` / `cannot()`
- `isRole()` / `isAdministrator()`
- `inRoles()` / `visible()`
- URL 权限中间件、菜单可见性、Grid 与详情页默认操作

因此，用户即使被分配了 `administrator` 角色，只要当前切换到普通角色，就不会获得管理员绕过权限。

## 自定义管理员模型

自定义 `admin.database.users_model` 必须继续提供 `roles()` 多对多关联，并使用 `Dcat\Admin\Traits\HasPermissions`（或实现同名的当前角色方法），才能参与当前角色授权。旧的自行复制版权限 trait 不会自动获得此能力。
